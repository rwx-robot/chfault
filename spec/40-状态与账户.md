# 40 · 状态与账户

> v0 用 MPT（Merkle Patricia Trie），与以太坊兼容；v1 评估 JMT。

---

## 1. 账户模型

**Account 模型**（非 UTXO）。

### 1.1 账户结构

| # | 字段 | 类型 | 说明 |
|---|------|------|------|
| 0 | `nonce` | uint64 | 交易序号，防重放与排序 |
| 1 | `balance` | uint256 | 余额（Wei） |
| 2 | `code_hash` | Bytes32 | 合约代码哈希；EOA 为空哈希 |
| 3 | `storage_root` | Bytes32 | 合约存储树根；EOA 为空树根 |

### 1.2 空哈希常量

```
EMPTY_CODE_HASH     = keccak256("") 
                    = 0xc5d2460186f7233c927e7db2dcc703c0e500b653ca82273b7bfad8045d85a470
EMPTY_STORAGE_ROOT  = keccak256(rlp(0x80))    // RLP 空串
                    = 0x56e81f171bcc55a6ff8345e692c0f86e5b48e01b996cadc001622fb5e363b421
```

这两个常量必须与以太坊一致（EVM 兼容性依赖它）。

### 1.3 EIP-158 空账户清理

若账户满足 `nonce == 0 && balance == 0 && code_hash == EMPTY_CODE_HASH`，
则在状态树中**删除**该账户（视为不存在）。

**这条规则很重要**：不清理会导致状态膨胀，且与其他以太坊实现不一致。

## 2. 合约代码存储

代码**不放在账户结构内**，按 `code_hash` 单独存储并去重：

```
key   = code_hash (32 字节)
value = 合约字节码
```

收益：多个账户部署同一份合约代码时只存一份。

## 3. MPT 结构（与以太坊兼容）

### 3.1 节点类型

| 类型 | 结构 | RLP 编码 |
|------|------|---------|
| **Empty** | — | `0x80`（空串） |
| **Leaf** | `[encoded_path, value]` | 2 元素列表 |
| **Extension** | `[encoded_path, child_hash]` | 2 元素列表 |
| **Branch** | `[c0..c15, value]` | 17 元素列表 |
| **Hash** | 节点引用 | 32 字节裸哈希（`>= 32` 字节的内联节点会被哈希化） |

### 3.2 路径编码（Hex Prefix Encoding）

nibble 序列 → 字节的前缀标记：

| 前缀 | 含义 |
|------|------|
| `0x0` | 扩展节点，**偶数**长度路径 |
| `0x1` | 扩展节点，**奇数**长度路径 |
| `0x2` | 叶子节点，偶数长度 |
| `0x3` | 叶子节点，奇数长度 |

```
encoded_path = prefix_byte ‖ packed_nibbles

prefix_byte = (flags << 4) | (odd ? first_nibble : 0x00)
```

奇数长度时，第一个 nibble 放进前缀字节的低 4 位。

### 3.3 键

- **状态树**：`keccak256(address)`（32 字节）
- **存储树**：`keccak256(storage_slot)`（32 字节）

两者都用哈希作为键，保证树是均匀分布的（防攻击者构造深路径）。

### 3.4 MPT 与二叉 Merkle 树的分工

| 用途 | 结构 |
|------|------|
| 账户状态、合约存储 | **MPT**（需要按 key 查找与 witness 证明） |
| 交易列表、收据列表 | **二叉 Merkle 树**（顺序固定，不需要按 key 查找） |

**不要**把交易树也做成 MPT —— 顺序固定的集合用简单 Merkle 树即可，更快更简单。

## 4. 状态会话与回滚

MPT 本身**不提供版本化回滚**。chfault 用 **journal** 实现：

```
Begin(parent_root):
    trie = open(parent_root)
    journal = []

SetXxx(key, value):
    old := trie.Get(key)
    journal.append({op: undo, key: key, old: old})
    trie.Set(key, value)

Savepoint() -> id:
    return len(journal)

RollbackTo(id):
    for i := len(journal)-1; i >= id; i--:
        journal[i].undo()          // 逆序回放
    journal = journal[:id]

Commit() -> new_root:
    root, nodes = trie.Commit()    // Merkle 化
    store.WriteBatch(nodes)
    return root
```

### 4.1 为什么必须有嵌套 savepoint

EVM 的 `REVERT` 语义要求能回滚到**单笔交易开始处**，而不只是整个区块开始处。
所以 `Savepoint`/`RollbackTo` 必须支持嵌套，不能只提供整体回滚。

### 4.2 gas 与回滚

回滚**不退还已消耗的 gas**。失败的交易仍然扣 gas 并产生 `status=0` 的收据。

## 5. 存储层布局（Pebble）

Pebble 没有列族，用 **1 字节 namespace 前缀**隔离：

| NS | 值 | 用途 |
|----|-----|------|
| `NSBlocks` | `0x01` | 区块、哈希索引 |
| `NSTxIndex` | `0x02` | 交易定位 |
| `NSReceipts` | `0x03` | 收据 |
| `NSConsensus` | `0x04` | 验证者集、QC、证据 |
| `NSMeta` | `0x05` | 链头、genesisHash、schemaVersion |
| `NSState` | `0x06` | MPT 节点 |
| `NSCode` | `0x07` | 合约代码 |

### 5.1 Key schema（大端编码）

| 用途 | Key | Value |
|------|-----|-------|
| 区块（按高度） | `0x01 ‖ 0x01 ‖ height(8BE)` | ssz(block) |
| 区块（按哈希） | `0x01 ‖ 0x02 ‖ hash(32)` | height(8BE) |
| 交易定位 | `0x02 ‖ txHash(32)` | height(8BE) ‖ txIndex(4BE) |
| 收据 | `0x03 ‖ height(8BE) ‖ txIndex(4BE)` | ssz(receipt) |
| 验证者集 | `0x04 ‖ 0x01 ‖ version(8BE)` | ssz(ValidatorSet) |
| QC | `0x04 ‖ 0x02 ‖ height(8BE)` | ssz(QC) |
| 证据 | `0x04 ‖ 0x03 ‖ height(8BE)` | ssz([]Evidence) |
| 链头 | `0x05 ‖ "chainTip"` | height ‖ hash ‖ stateRoot |
| genesisHash | `0x05 ‖ "genesisHash"` | 32 bytes |
| schemaVersion | `0x05 ‖ "schemaVersion"` | uint32 BE |
| MPT 节点 | `0x06 ‖ nodeHash(32)` | rlp(node) |
| 合约代码 | `0x07 ‖ codeHash(32)` | code |

**整数一律大端**，保证字节序 = 数值序（支持范围扫描）。

### 5.2 原子性

一次区块提交 = **一个 Pebble Batch**。
**区块数据与状态节点必须在同一 Batch 提交**，否则崩溃会产生"有区块无状态"的不一致。

## 6. 状态同步与快照

```
Checkpoint(dir) -> 硬链接快照（秒级，几乎零成本）
manifest.json = { height, state_root, block_hash, chunk_hashes[] }
```

切片默认 64 MiB，peer 下载后逐片校验哈希。

**v0 信任模型**：多 peer 交叉校验 + 管理员可钉可信快照哈希。
（**v2 公链路径必须替换为轻客户端验证**，见 `docs/blueprint/10`。）
