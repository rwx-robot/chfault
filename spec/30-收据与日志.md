# 30 · 收据与日志

---

## 1. 收据（Receipt）

每笔交易执行后产生一条收据，用于状态验证与事件查询。

### 1.1 字段表

| # | 字段 | 类型 | 说明 |
|---|------|------|------|
| 0 | `status` | uint8 | `1` = 成功，`0` = 失败（revert）。**禁止其他值** |
| 1 | `tx_hash` | TxHash | 32 字节 |
| 2 | `gas_used` | uint64 | 本笔交易实际消耗 |
| 3 | `cumulative_gas_used` | uint64 | 区块内累计（含本笔） |
| 4 | `logs_bloom` | Bytes256 | 本笔交易日志的布隆过滤器 |
| 5 | `logs` | list of Log | 按产生顺序 |
| 6 | `contract_address` | Address \| null | 仅合约创建交易有值 |
| 7 | `effective_gas_price` | uint256 | 实际单价 = base_fee + priority |

### 1.2 编码

SSZ 容器。`logs` 与 `contract_address` 是变长/可选字段，走 offset 机制。

---

## 2. 日志（Log）

| # | 字段 | 类型 | 说明 |
|---|------|------|------|
| 0 | `address` | Address | 产生日志的合约地址 |
| 1 | `topics` | list of Bytes32 | **最多 4 个**；超过即执行失败 |
| 2 | `data` | Bytes | 非索引数据 |

**`topics` 上限 4** 是 EVM 的规定（`LOG0`–`LOG4`）。解析到 5 个 topic 应视为数据损坏。

---

## 3. 布隆过滤器（Bloom，256 字节）

### 3.1 构造算法（与以太坊一致）

```
bloom = 256 字节全零

对每条日志：
    // 加入合约地址
    bloom_add(bloom, keccak256(log.address))
    // 加入每个 topic
    for topic in log.topics:
        bloom_add(bloom, keccak256(topic))

func bloom_add(bloom []byte, hash [32]byte):
    for i in 0..2:
        // 取 hash 的第 2i, 2i+1 字节，低 11 位作为 bit 位置
        bitpos = uint16(hash[2i] & 0x07)<<8 | uint16(hash[2i+1])
        // 注意：是 (bitpos & 0x7FF)，共 2048 bits = 256 bytes
        byte_index = 255 - (bitpos / 8)     // 反转字节序
        bit_index  = bitpos % 8
        bloom[byte_index] |= (1 << bit_index)
```

**关键细节**：
- 位位置取 `hash` 每两字节的**低 11 位**（`& 0x07FF`），共 3 组 → 设置 3 个 bit
- 字节索引是**反转**的（`255 - bitpos/8`），这是以太坊的历史设计，必须照做
- 布隆过滤器**只用于快速过滤，会有假阳性**；精确匹配必须回查原始日志

### 3.2 用途

`eth_getLogs` 先用区块头的 `logs_bloom` 过滤区块，再用每条收据的 `logs_bloom` 过滤交易，
最后精确匹配 topics。**三级过滤**，避免全表扫描。

## 4. 收据根（ReceiptRoot）

区块内所有收据按**交易顺序**组成的列表，用 §01.7 的二叉 Merkle 树计算：

```
leaves[i] = ssz_hash_tree_root(receipt[i])
receipt_root = merkle_root(leaves)
```

**顺序即交易顺序，不重排。**
空列表 → 32 字节零。

## 5. 状态根与收据的关系

```
执行区块:
  for i, tx := range txs:
      sp := session.Savepoint()
      result, err := vm.RunTx(session, tx, ctx)
      if err != nil || !result.Success {
          session.RollbackTo(sp)      // 回滚状态，但 gas 仍消耗
      }
      receipt[i] = buildReceipt(result, cumulativeGas)
      // 注意：失败的交易也产生收据（status=0）
```

**失败的交易也产生收据**（`status=0`），这样能查到失败原因与 gas 消耗。
