# 20 · 区块头与区块体

> 区块头必须**可自证**：携带最终性证明与验证者集承诺，使轻客户端与同步节点能独立验证。

---

## 1. 区块头（BlockHeader）

### 1.1 字段表（SSZ 容器，序列化顺序即声明顺序）

| # | 字段 | 类型 | 长度 | 说明 |
|---|------|------|------|------|
| 0 | `version` | uint16 | 2 | 硬分叉版本，按高度激活 |
| 1 | `chain_id` | uint64 | 8 | EIP-155 重放保护 |
| 2 | `height` | uint64 | 8 | 区块高度，创世为 0 |
| 3 | `round` | uint32 | 4 | **共识轮次（逻辑时钟）**，非 wall clock |
| 4 | `timestamp` | uint64 | 8 | 秒级 Unix 时间，受共识规则约束 |
| 5 | `prev_hash` | BlockHash | 32 | 前一区块哈希；创世为 32 字节零 |
| 6 | `proposer` | Address | 20 | 提议者地址 |
| 7 | `tx_root` | TxRoot | 32 | 交易列表的 Merkle 根 |
| 8 | `receipt_root` | ReceiptRoot | 32 | 收据列表的 Merkle 根 |
| 9 | `state_root` | StateRoot | 32 | 执行后状态根 |
| 10 | `logs_bloom` | Bytes256 | 256 | EVM 日志布隆过滤器 |
| 11 | `gas_used` | uint64 | 8 | |
| 12 | `gas_limit` | uint64 | 8 | |
| 13 | `base_fee_per_gas` | uint256 | 32 | EIP-1559 基础费 |
| 14 | `consensus` | ConsensusMeta | 变长 | 见 §2 |
| 15 | `extra_data` | Bytes | 变长 | ≤ 32 字节，运营方自定义 |

**固定部分大小**：2+8+8+4+8+32+20+32+32+32+256+8+8+32 = 482 字节
（不含 `consensus`、`extra_data` 两个变长字段）

### 1.2 为什么这样设计（相对原始方案的修正）

| 原方案问题 | 本规范处理 |
|-----------|-----------|
| 只有 `merkleRoot`，语义不明 | 拆为 `tx_root` + `receipt_root` |
| 缺 `logs_bloom` | 补上（EVM 兼容必需） |
| `attestations` 放区块体，header 无法自证 | 移入 `consensus.precommit_qc` |
| `timestamp: number` 用 wall clock 驱动共识 | 增加 `round` 作为逻辑时钟；`timestamp` 受共识规则约束 |
| 单一 `gasPrice` | 改为 `base_fee_per_gas`（EIP-1559） |
| 无验证者集承诺 | 增加 `consensus.validator_set_hash` |

## 2. ConsensusMeta

| # | 字段 | 类型 | 说明 |
|---|------|------|------|
| 0 | `precommit_qc` | QuorumCertificate \| null | 前一高度的 precommit 聚合证明 |
| 1 | `validator_set_hash` | Bytes32 | 当前验证者集哈希 |

SSZ 可变联合体：`precommit_qc` 为 null 时用 selector `0x00`，有值时 `0x01` 后跟内容。

**创世区块**：`precommit_qc = null`。

---

## 3. 区块体（BlockBody）

| # | 字段 | 类型 | 说明 |
|---|------|------|------|
| 0 | `transactions` | list of Transaction | 按执行顺序（打包顺序即执行顺序） |

**v0 区块体只含交易。**  attestations/证据不在区块体（证据通过 `consensus` 通道另行处理，见 50 章）。

---

## 4. 区块哈希

```
block_hash = keccak256(ssz_serialize(block_header))
```

**只哈希区块头**，不含区块体。
理由：轻客户端只需头即可验证链的连续性；区块体通过 `tx_root` 绑定。

---

## 5. 区块编码（完整）

```
block = uint32_le(header_len) ‖ ssz(header) ‖ uint32_le(body_len) ‖ ssz(body)
```

网络传输与存储均用此格式。长度前缀用**小端 uint32**（SSZ 惯例）。

---

## 6. 创世区块

```
height          = 0
round           = 0
prev_hash       = 0x0000...0000 (32 字节零)
proposer        = 0x0000...0000 (20 字节零)
tx_root         = 空列表根 = 0x0000...0000
receipt_root    = 空列表根 = 0x0000...0000
state_root      = 由 genesis 分配计算得出
logs_bloom      = 256 字节零
gas_used        = 0
gas_limit       = 配置值
base_fee_per_gas= 配置值（initialBaseFeeWei）
consensus.precommit_qc = null
```

**创世必须由 `(chain_id, 初始分配, 初始验证者集)` 确定性推导**。
相同输入必须产生相同的 `genesis_hash`，这是多节点能组网的前提。

创世文件（JSON）包含：
```json
{
  "chain_id": "10086",
  "timestamp": "1700000000",
  "gas_limit": "30000000",
  "initial_base_fee": "1000000000",
  "alloc": { "0x<addr>": { "balance": "1000000000000000000" } },
  "validators": [ { "address": "0x...", "pubkey": "0x...", "power": "1" } ],
  "extra_data": "0x"
}
```

`alloc` 与 `validators` 必须**按键排序**（地址字节序升序）后再计算 state_root，
保证相同内容产生相同哈希。

## 7. 校验规则（收到区块时逐条执行）

| 序 | 检查 | 失败处理 |
|----|------|---------|
| 1 | `header_len`/`body_len` 与实际一致 | 拒绝区块 |
| 2 | `chain_id` 匹配 | 拒绝 |
| 3 | `height == parent.height + 1` | 拒绝 |
| 4 | `prev_hash == parent_hash` | 拒绝 |
| 5 | `timestamp > parent.timestamp` | 拒绝 |
| 6 | `timestamp <= local_time + MAX_CLOCK_DRIFT(5s)` | 拒绝 |
| 7 | `timestamp >= 2f+1 个验证者上报时间的中位数` | 拒绝 |
| 8 | `gas_used <= gas_limit` | 拒绝 |
| 9 | `logs_bloom` 长度 == 256 | 拒绝 |
| 10 | `extra_data` 长度 <= 32 | 拒绝 |
| 11 | `consensus.validator_set_hash` 与本地推导一致 | 拒绝 |
| 12 | `consensus.precommit_qc` 对 parent 高度有效（签名数与阈值） | 拒绝 |
| 13 | `tx_root` == 区块体交易列表的 Merkle 根 | 拒绝 |
| 14 | **执行后** `state_root` == 本地计算结果 | **停节点**（最严重） |

第 14 条失败意味着分叉或执行 bug，**绝不静默继续**。
