# 01 · 编码原语

> 本文定义所有结构共用的编码规则。后续章节直接引用这里的类型名。

---

## 1. 基本类型编码

| 类型 | 长度 | 编码 |
|------|------|------|
| `uint8` | 1 | 无符号大端 |
| `uint16` | 2 | 无符号大端 |
| `uint32` | 4 | 无符号大端 |
| `uint64` | 8 | 无符号大端 |
| `uint256` | 32 | 无符号大端（用于金额） |
| `bool` | 1 | `0x00` = false，`0x01` = true。**禁止其他值**，解析到非 0/1 即报错 |
| `BytesN` | N | 原样 N 字节，无长度前缀 |
| `Bytes` | 变长 | SSZ 可变长（见 §3） |

### uint256 的规范形式

`uint256` 必须序列化为**固定 32 字节**，即使数值很小。

```
值 1  → 0x0000...0001  (31 个 0x00 后跟 0x01)
值 0  → 0x0000...0000  (32 个 0x00)
```

**禁止**去除前导零（会导致长度不定，破坏定长布局）。

## 2. Hash / Address 类型

| 类型 | 底层 | 长度 |
|------|------|------|
| `Hash` | `Bytes32` | 32 |
| `Address` | `Bytes20` | 20 |
| `BlockHash` | `Hash` | 32 |
| `TxHash` | `Hash` | 32 |
| `StateRoot` | `Hash` | 32 |
| `TxRoot` | `Hash` | 32 |
| `ReceiptRoot` | `Hash` | 32 |

这些是**语义不同的具名类型**。实现中必须用不同的 Go 类型（而非裸 `[32]byte`），
编译期阻止把 `TxRoot` 当 `StateRoot` 传。

## 3. SSZ 可变长编码（offset 机制）

SSZ 把结构分成**固定部分**与**可变部分**：

```
[ 固定大小字段 1 ][ 固定大小字段 2 ][ offset_1 ][ offset_2 ][ 可变字段 1 ][ 可变字段 2 ]
                                    ^^^^^^^^^^^^^^^^^^^^^^   ^^^^^^^^^^^^^^^^^^^^^^^^^
                                    固定部分中的 4 字节小端偏移   实际数据（按出现顺序）
```

规则：

1. 固定大小字段（uintN、bool、BytesN）**直接内联**
2. 变长字段在固定部分占 **4 字节**，值是该字段数据区**相对于整个结构起始的字节偏移**
3. offset 用**小端** uint32（这是 SSZ 规范的规定，与本规范的大端原则不冲突 —— offset 是 SSZ 内部结构，不是协议整数）
4. 变长数据在固定部分之后，**按字段声明顺序**依次排列
5. 若字段是"变长元素的列表"（如 `[]Bytes`），offset 指向的元素区每个元素再带一个相对偏移

### 示例

```go
type Demo struct {
    Nonce    uint64   // 固定，8 字节
    To       Address  // 固定，20 字节
    Data     Bytes    // 变长
}
```

编码布局：

```
偏移 0:  Nonce  (8 字节, 大端)
偏移 8:  To     (20 字节)
偏移 28: offset_Data (4 字节小端) = 32
偏移 32: Data 内容（len(Data) 字节）
```

若 `Data = 0xdeadbeef`（4 字节），完整编码为 36 字节。

## 4. 地址编码

### 4.1 二进制形式

20 字节原始字节，无校验和。参与哈希与状态存储一律用二进制形式。

### 4.2 文本形式（EIP-55 校验和）

仅用于 **显示与 RPC 输出**，不参与哈希。

```
1. 对地址小写十六进制（去掉 0x）做 keccak256
2. 若哈希的第 i 个十六进制位 >= 8，则地址第 i 位大写，否则小写
3. 前缀 0x
```

例：`0x5aAeb6053F3E94C9b9A09f33669435E7Ef1BeAed`

**规则**：内部计算与存储一律用小写二进制；只在边界（显示/RPC 输出）转换为 EIP-55。

---

## 5. 十六进制（Base16）表示

用于 JSON（测试向量、RPC、配置）：

- 必须带 `0x` 前缀
- 字节用**小写**十六进制（`0xff` 而非 `0xFF`）
- 长度必须是偶数（每字节 2 个字符）
- 空字节序列表示为 `0x`

**RPC 中的所有数量（quantity）**也用十六进制字符串：`0x0`、`0x1`、`0x400`。
**禁止**用 JSON number 表示 uint64/uint256（会丢精度）。

## 6. 哈希计算

### 6.1 Keccak-256

```
keccak256(data) → 32 字节
```

用于：地址派生（公钥 → 地址）、交易哈希、区块哈希、EVM 内部。

**注意**：Keccak-256 ≠ SHA3-256。两者的 padding 常量不同
（Keccak 用 `0x01`，SHA3 用 `0x06`）。实现必须使用 Keccak-256。

### 6.2 SSZ hash_tree_root

用于共识消息与 Merkle 化：

```
hash_tree_root(x):
    - 基本类型：打包进 32 字节 chunk（小端）
    - BytesN：若为 32 字节则直接用，否则 pack
    - 向量/列表：Merkkle 化（必要时补零到 2 的幂）
    - 容器：各字段 hash_tree_root 再 Merkle 化
```

Merkle 化时**零填充到下一个 2 的幂**，缺失叶子用 32 字节零。

## 7. Merkle 树（用于交易树、收据树）

顺序固定的列表用**二叉 Merkle 树**（不是 MPT）：

```
leaves = [h(item_0), h(item_1), ..., h(item_n-1)]
若 len(leaves) == 0 → root = 32 字节零

层：
  level_0 = leaves（若奇数个，最后一个与自己配对）
  level_{i+1}[j] = keccak256(level_i[2j] ‖ level_i[2j+1])
  root = 最后一层唯一元素
```

**奇数个叶子的处理**：最后一个叶子与自己配对（即 `h = keccak256(x ‖ x)`）。
这个规则必须写死，不同实现必须一致。

**空列表**：root = `0x0000...0000`（32 字节零），不是空哈希。

## 8. 排序规则（确定性关键）

任何集合在参与哈希/序列化前必须显式排序：

| 集合 | 排序键 |
|------|--------|
| 验证者集 | `Address` 字节序升序 |
| 交易列表（区块内） | 打包时确定的顺序（不重排） |
| 日志 | 产生顺序（不重排） |
| 存储槽（witness） | 槽的字节序升序 |

**Go 实现警告**：`map` 的遍历顺序是随机化的。
必须先 `keys := slices.Sorted(maps.Keys(m))`，再按序遍历。
（`internal/lint/determinism` 会拦截核心包的 `range map`。）

## 9. 错误码（解析层）

| 码 | 名称 | 含义 |
|----|------|------|
| `E001` | `ERR_TRUNCATED` | 数据不足 |
| `E002` | `ERR_TRAILING_BYTES` | 解析后仍有剩余字节 |
| `E003` | `ERR_BAD_BOOL` | bool 值非 0/1 |
| `E004` | `ERR_BAD_OFFSET` | SSZ offset 越界或递减 |
| `E005` | `ERR_BAD_LENGTH` | 长度前缀超过剩余数据 |
| `E006` | `ERR_OVERSIZED` | 超过 `MAX_*` 常量 |
| `E007` | `ERR_BAD_CHAIN_ID` | chainId 不匹配 |
