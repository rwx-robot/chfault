# 10 · 交易

> 对齐以太坊 EIP-2718 / EIP-1559 / EIP-155，**不发明新格式**。

---

## 1. 交易信封（EIP-2718）

```
transaction = tx_type ‖ tx_payload       // 仅 typed transaction
transaction = rlp([...])                 // legacy 无类型前缀
```

| 类型字节 | 含义 | v0 支持 |
|---------|------|--------|
| `0x00`–`0x7f` | typed transaction 的类型标识 | |
| `0x02` | **EIP-1559 动态费用交易** | ✅ 主要 |
| `0x01` | EIP-2930 访问列表交易 | ✅ 可解析，CLI/SDK 不生成 |
| `0xc0`–`0xfe` | legacy transaction（RLP 列表首字节） | ✅ 兼容保留 |

**解析流程**：读第 1 字节
- 若 `<= 0x7f` → typed，按类型解析 payload
- 若 `>= 0xc0` → legacy，整串按 RLP 列表解析
- 其他 → `E003` 错误

## 2. EIP-1559 交易（type = 0x02）

### 2.1 签名载荷（参与签名与哈希）

```
rlp([
    chain_id,
    nonce,
    max_priority_fee_per_gas,
    max_fee_per_gas,
    gas_limit,
    destination,          // 20 字节地址；合约创建时为空串
    amount,
    data,
    access_list,
])
```

| 字段 | 类型 | 说明 |
|------|------|------|
| `chain_id` | uint256 | 防跨链重放 |
| `nonce` | uint64 | 发送者交易序号 |
| `max_priority_fee_per_gas` | uint256 | 给 proposer 的小费上限 |
| `max_fee_per_gas` | uint256 | 总费用上限（含 baseFee） |
| `gas_limit` | uint64 | |
| `destination` | Address(20) 或空 | 空串表示合约创建 |
| `amount` | uint256 | 转账金额（Wei） |
| `data` | bytes | 调用数据 / 构造代码 |
| `access_list` | list of [address, [storage_key...]] | EIP-2930 |

### 2.2 签名

```
sig_payload_hash = keccak256(0x02 ‖ rlp(signing_payload))
signature        = secp256k1_sign(sig_payload_hash, private_key)
                   → 65 字节：r(32) ‖ s(32) ‖ v(1)
```

**v 的语义（EIP-155）**：typed transaction 中 `v` 是 **0 或 1**（y_parity），
不是 legacy 的 `27/28` 也不是 `chainId*2+35/36`。

**s 的规范化（EIP-2）**：`s` 必须 `<= secp256k1.N / 2`，否则签名无效（防可塑性攻击）。

### 2.3 完整编码

```
0x02 ‖ rlp([
    chain_id, nonce, max_priority_fee_per_gas, max_fee_per_gas,
    gas_limit, destination, amount, data, access_list,
    y_parity, r, s
])
```

### 2.4 交易哈希

```
tx_hash = keccak256(0x02 ‖ rlp(signing_payload))
```

**注意**：是 `signing_payload`（不含签名），不是完整交易。

## 3. Legacy 交易（type = 无，兼容保留）

```
rlp([nonce, gas_price, gas_limit, to, value, data, v, r, s])
```

EIP-155 规则：

```
v = {0,1} + chain_id * 2 + 35
```

解析时从 `v` 反推 `chain_id` 并校验匹配；`v ∈ {27,28}` 视为**无 chainId 保护**的旧交易，
**v0 拒绝**（不提供向后兼容到 2016 年的自由）。

## 4. 发送者恢复

```
pubkey = secp256k1_recover(sig_payload_hash, r, s, v)
sender = keccak256(pubkey[1:])[12:]      // 取后 20 字节
```

若恢复失败（签名无效）→ 交易无效，**不进入 mempool**。

## 5. 字段校验（mempool 准入，按顺序快速失败）

| 序 | 检查 | 错误 |
|----|------|------|
| 1 | 编码长度 ≤ `MAX_TX_SIZE`（128 KiB） | `ERR_OVERSIZED` |
| 2 | 类型 ∈ {0x02, 0x01, legacy} | `ERR_UNSUPPORTED_TYPE` |
| 3 | `chain_id` 匹配本链 | `ERR_BAD_CHAIN_ID` |
| 4 | 签名格式合法（r/s/v 长度与范围） | `ERR_BAD_SIGNATURE` |
| 5 | `s <= N/2` | `ERR_BAD_SIGNATURE` |
| 6 | 发送者恢复成功 | `ERR_BAD_SIGNATURE` |
| 7 | `gas_limit <= block_gas_limit` | `ERR_GAS_LIMIT` |
| 8 | `max_fee_per_gas >= current_base_fee` | `ERR_FEE_TOO_LOW` |
| 9 | `max_fee_per_gas >= max_priority_fee_per_gas` | `ERR_FEE_TOO_LOW` |
| 10 | `balance >= gas_limit * max_fee_per_gas + amount` | `ERR_INSUFFICIENT_FUNDS` |
| 11 | `nonce >= account.nonce` | `ERR_NONCE_TOO_LOW` |

检查 1–6 是**静态校验**（不查状态），7–11 需要状态。

---

## 6. 有效小费（排序用）

```
effective_priority_fee = min(
    max_priority_fee_per_gas,
    max_fee_per_gas - base_fee
)
```

mempool 按 `effective_priority_fee` 降序排序；
**同值时用 `tx_hash` 升序做 tie-break**（保证确定性，禁止依赖 map 顺序）。
